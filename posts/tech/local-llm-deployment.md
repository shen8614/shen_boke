    14|    14|# 本地大模型部署实战：Ollama + Open WebUI
    15|    15|
    16|    16|## 为什么要本地部署

    45|    45|
    46|    46|云端 API 方便，但有几个绕不开的问题：数据隐私（公司代码不想发到第三方服务器）、成本（大量调用时 API 费用很高）、离线需求（没网的时候也要能用）。本地部署大模型就是为了解决这些问题。
    47|    47|
    48|    48|2026 年的开源模型质量已经有了质的飞跃。Llama 3.3、Qwen 2.5、DeepSeek V3、Mistral Large 等模型在很多任务上已经接近甚至超过 GPT-4。配合量化技术，7B 参数的模型在普通笔记本上就能流畅运行。
    49|    49|
    50|    50|## Ollama：最简单的本地模型运行方案
    51|    51|
    52|    52|Ollama 是目前最简单的本地大模型运行工具。一行命令安装，一行命令跑模型，不需要 CUDA 配置、不需要 Python 环境、不需要理解量化参数。
    53|    53|
    54|    54|### 安装
    55|    55|
    56|    56|```bash
    57|    57|# Linux / WSL
    58|    58|curl -fsSL https://ollama.ai/install.sh | sh
    59|    59|
    60|    60|# macOS
    61|    61|brew install ollama
    62|    62|
    63|    63|# Windows
    64|    64|# 从 https://ollama.ai 下载安装包
    65|    65|```
    66|    66|
    67|    67|### 下载并运行模型
    68|    68|
    69|    69|```bash
    70|    70|# 下载并运行 Llama 3.3 8B
    71|    71|ollama run llama3.3
    72|    72|
    73|    73|# 下载并运行 Qwen 2.5 7B
    74|    74|ollama run qwen2.5
    75|    75|
    76|    76|# 下载并运行 DeepSeek V3
    77|    77|ollama run deepseek-v3
    78|    78|
    79|    79|# 下载并运行 CodeLlama（代码专用）
    80|    80|ollama run codellama
    81|    81|```
    82|    82|
    83|    83|第一次运行会自动下载模型文件，之后就是秒启。模型文件存在 `~/.ollama/models/` 下。
    84|    84|
    85|    85|### 常用命令
    86|    86|
    87|    87|```bash
    88|    88|# 查看已下载的模型
    89|    89|ollama list
    90|    90|
    91|    91|# 查看运行中的模型
    92|    92|ollama ps
    93|    93|
    94|    94|# 删除模型
    95|    95|ollama rm llama3.3
    96|    96|
    97|    97|# 显示模型信息
    98|    98|ollama show llama3.3
    99|    99|
   100|   100|# 停止运行中的模型
   101|   101|ollama stop llama3.3
   102|   102|```
   103|   103|
   104|   104|### API 调用
   105|   105|
   106|   106|Ollama 启动后会自动暴露一个 REST API（默认 `http://localhost:11434`），兼容 OpenAI API 格式：
   107|   107|
   108|   108|```bash
   109|   109|# 聊天补全
   110|   110|curl http://localhost:11434/v1/chat/completions \
   111|   111|  -H "Content-Type: application/json" \
   112|   112|  -d '{
   113|   113|    "model": "llama3.3",
   114|   114|    "messages": [{"role": "user", "content": "你好"}]
   115|   115|  }'
   116|   116|
   117|   117|# 文本生成
   118|   118|curl http://localhost:11434/api/generate \
   119|   119|  -d '{"model": "llama3.3", "prompt": "写一首关于春天的诗"}'
   120|   120|```
   121|   121|
   122|   122|这意味着你可以把 Ollama 当作 OpenAI API 的本地替代品，任何支持 OpenAI API 的工具都能无缝切换。
   123|   123|
   124|   124|## Open WebUI：给 Ollama 加个好看的界面
   125|   125|
   126|   126|Ollama 本身只有命令行交互，Open WebUI 给它加了一个类似 ChatGPT 的 Web 界面。
   127|   127|
   128|   128|### 安装（Docker 方式）
   129|   129|
   130|   130|```bash
   131|   131|docker run -d -p 3000:8080 \
   132|   132|  --add-host=host.docker.internal:host-gateway \
   133|   133|  -v open-webui:/app/backend/data \
   134|   134|  --name open-webui \
   135|   135|  --restart always \
   136|   136|  ghcr.io/open-webui/open-webui:main
   137|   137|```
   138|   138|
   139|   139|安装完成后访问 `http://localhost:3000`，首次访问需要注册一个管理员账号。
   140|   140|
   141|   141|### 连接 Ollama
   142|   142|
   143|   143|Open WebUI 会自动检测本地运行的 Ollama 实例。如果没有自动识别，在设置里把 Ollama API 地址填为 `http://host.docker.internal:11434`（Docker 环境）或 `http://localhost:11434`（直接安装）。
   144|   144|
   145|   145|### 主要功能
   146|   146|
   147|   147|- **多模型切换**：下拉框切换不同模型，对比效果
   148|   148|- **对话管理**：历史对话、文件夹分类、搜索
   149|   149|- **文件上传**：上传 PDF/文档让模型分析
   150|   150|- **RAG**：上传文档建立知识库，模型基于文档回答
   151|   151|- **Prompt 模板**：预设常用 prompt，一键调用
   152|   152|- **多用户**：支持多用户注册，各自独立的对话历史
   153|   153|
   154|   154|## 模型选型建议
   155|   155|
   156|   156|不同场景推荐不同的模型：
   157|   157|
   158|   158|| 场景 | 推荐模型 | 参数量 | 显存需求 |
   159|   159||------|----------|--------|----------|
   160|   160|| 日常对话 | Qwen 2.5 7B | 7B | 4GB |
   161|   161|| 代码生成 | DeepSeek Coder V2 | 16B | 10GB |
   162|   162|| 通用能力 | Llama 3.3 8B | 8B | 5GB |
   163|   163|| 长文本处理 | Qwen 2.5 32B | 32B | 20GB |
   164|   164|| 复杂推理 | DeepSeek V3 | 671B (MoE) | 需要多卡 |
   165|   165|
   166|   166|### 量化版本
   167|   167|
   168|   168|显存不够时可以用量化版本。Ollama 默认使用 Q4_K_M 量化，在质量和体积之间取了平衡：
   169|   169|
   170|   170|```bash
   171|   171|# Q4 量化（默认，体积小，速度快）
   172|   172|ollama run llama3.3
   173|   173|
   174|   174|# Q8 量化（质量更好，体积翻倍）
   175|   175|ollama run llama3.3:8b-q8_0
   176|   176|
   177|   177|# FP16 全精度（质量最好，需要更大显存）
   178|   178|ollama run llama3.3:8b-fp16
   179|   179|```
   180|   180|
   181|   181|### 没有显卡怎么办
   182|   182|
   183|   183|Ollama 支持纯 CPU 运行，只是速度会慢很多。7B 模型在 16GB 内存的笔记本上用 CPU 跑，生成速度大约 5-10 token/s，勉强可用。如果经常用，建议至少配一块 8GB 显存的显卡（RTX 4060 之类的），体验会好很多。
   184|   184|
   185|   185|## 进阶：自定义模型
   186|   186|
   187|   187|Ollama 支持通过 Modelfile 自定义模型行为：
   188|   188|
   189|   189|```dockerfile
   190|   190|# Modelfile
   191|   191|FROM qwen2.5
   192|   192|
   193|   193|SYSTEM """
   194|   194|你是一个专业的 Java 后端开发助手。
   195|   195|回答问题时使用中文，代码示例使用 Spring Boot 3.x。
   196|   196|"""
   197|   197|
   198|   198|PARAMETER temperature 0.7
   199|   199|PARAMETER num_ctx 4096
   200|   200|```
   201|   201|
   202|   202|```bash
   203|   203|# 创建自定义模型
   204|   204|ollama create my-java-assistant -f Modelfile
   205|   205|
   206|   206|# 运行
   207|   207|ollama run my-java-assistant
   208|   208|```
   209|   209|
   210|   210|这样你就可以针对不同场景创建不同的模型变体，而不需要每次手动输入 system prompt。
   211|   211|
   212|   212|## 实际使用体验
   213|   213|
   214|   214|我在一台 RTX 4060（8GB 显存）的机器上跑 Qwen 2.5 7B，配合 Open WebUI 日常使用了两个月：
   215|   215|
   216|   216|**满意的方面**：响应速度快（首 token 延迟 0.5s 左右），中文能力不错，完全离线可用。用它来做代码解释、写注释、简单重构完全够用。
   217|   217|
   218|   218|**不满意的方面**：复杂推理能力还是比不上云端大模型。写长篇代码时容易前后不一致，需要手动修正。另外本地模型的上下文窗口通常比较短（4K-8K），处理长文档时需要分段。
   219|   219|
   220|   220|**建议**：把本地模型当作"快速助手"而不是"专家顾问"。简单问题用本地模型秒回，复杂问题再调云端 API。这样既省成本又不牺牲质量。
